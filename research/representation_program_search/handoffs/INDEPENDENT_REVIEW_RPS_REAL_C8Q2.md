# Independent DEV-admission review — `rps-real-c8q2`

Reviewer disposition: **DIAGNOSTIC_ONLY**

The package is mechanically strong but is not admissible as the missing
R4/R5 DEV calibration case.  Its exact executable content is a fixed
three-member seed/derivative/linear-recurrence chain, independently assessed
as **R1 at best**, not an operational R5 special-function representation.
The package remains useful as a primitive-grammar and public-loader smoke
diagnostic.  It must not count as R3+ or special-function discovery evidence.

This review did not modify the package, parser, verifier, Program IR, grammar,
search, benchmark manifests, or any historical artifact.  It made no model
call and selected no TEST identity.

## Assumption audit

The exact algebraic obligations are assumption-complete:

- P8A1 declares `x` real and nonzero.  Restricting identities stated for
  complex `z` to this real subdomain is valid.
- P8A3 follows from P8A1: every displayed denominator is a power of `x`.
- No sign, positivity, boundary condition, zero-limit continuation, or
  folklore physical assumption is needed.
- Orders 0, 1, and 2 are fixed integers, so there is no unresolved order
  domain in the evaluator-side source interpretation.

P8A2 is nevertheless problematic on the proposer boundary.  The public
expressions contain no order symbol and the verifier has no order-domain
predicate to check.  Telling the proposer that these three opaque members are
"orders 0, 1, and 2" supplies adjacent-family semantics and, in catalog order,
strongly suggests their roles.  This is not a literal operator-name leak, but
it is avoidable target-role information under the hidden-member-role policy.

## Minimum sufficient operational depth

Stripping presentation labels, the complete executable program is:

```text
F(u) = sin(u)/u
c0   = F(x)
c1   = -dF(u)/du |_(u=x)
c2   = (3/x)*c1 - c0
```

That graph has one latent kernel and five primitive operations: `VALUE`,
`DERIVATIVE`, `SUBSTITUTE`, and two `LINEAR_COMBINATION`s.  `c0` is exactly the
first source member.  The program neither:

- creates a latent object `j_n` or another special-function object;
- encodes a symbolic nonnegative order `n`;
- applies the general Rayleigh operator `n` times;
- encodes a general recurrence transition in `n`; nor
- reconstructs any order beyond the fixed three displayed members.

The `instance_maps.order` values are metadata and do not participate in
compilation.  Calling the fixed outputs spherical Bessel functions happens
only in evaluator/source interpretation.  Under the minimum-sufficient rule,
this is a small adjacent-family recurrence/derivative representation—R1 at
best—not an R5 representation change.  Its success under `G_PRIMITIVE` is a
useful control, but it reinforces the depth downgrade rather than rescuing
R5.

## Final admission boundary

**DIAGNOSTIC_ONLY.** Preserve the package as evidence that the public loader,
strict M1 constructor, primitive grammar, and exact verifier can execute a
small real-domain family.  Do not admit it as the DEV R4/R5 calibration case,
do not count it toward the requested R2--R8 benchmark balance, and do not use
it for an AI-search or grammar-invention claim.

A future admissible R5 case would need an operational representation change
that the program actually constructs—not merely an evaluator-side
special-function name—and a public assumption surface containing only needed
domain predicates.  This review does not propose or authorize such a package
rewrite.
